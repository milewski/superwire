---
title: Workflows
description: See how declarations combine into a complete workflow file and final output object.
---

A workflow is the complete `.ai` file. The top-level grammar is intentionally small so most of the complexity stays inside agents and type expressions.

## Full workflow anatomy

```ai
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

secrets {
    openai_api_key: string
}

input {
    study_name: string
    interview_notes: [string]
}

schema Brief {
    summary: string
    recommendations: [string]
}

agent summarize_notes {
    model: openai("gpt-4.1-mini")
    prompt: "Summarize {{ input.interview_notes }} for {{ input.study_name }}."
    output: schema.Brief
}

output {
    study_name: input.study_name
    summary: agent.summarize_notes.summary
    recommendations: agent.summarize_notes.recommendations
}
```

## Final output block

The `output` declaration is an object expression, not a type block.

That means each field can be built from:

- literals (strings, numbers, booleans)
- references (`agent.name`, `input.field`)
- arrays (`[1, 2, 3]`)
- objects (`{ key: value }`)
- interpolated strings

```ai
output {
    version: 2
    generated_by: "research_brief"
    report: {
        summary: agent.summarize_notes.summary
        recommendation_count: 3
    }
}
```

## Inputs and secrets

The language distinguishes normal input from secret declarations:

- `input` is for regular business data
- `secrets` is for sensitive configuration and credentials

Validation prevents `secrets.*` references from being used in prompts, context, and workflow output.

The current public runtime API accepts typed input values directly. Secret declaration support is available in the DSL and validator.

## Optional output declaration

The grammar allows workflows without a top-level `output` block. In the current runtime, omitting `output` yields an empty JSON object.

<Tip>
  Most production workflows should still define `output` explicitly so the
  public result stays stable even when agent internals change.
</Tip>
