Agents are the center of the DSL. They describe a named unit of work that can reference input, secrets, and prior agent outputs.

## Basic syntax

```wire
agent summary {
    model: openai("gpt-4.1-mini")
    instruction: "Summarize {{ input.notes }}."
    output: string
}
```

## Agent declaration form

```wire
agent <name> [for <item> in <expression>] {
    model: <expression>
    instruction: <expression>
    output: <type_expression>
    context: <expression>
    inference: <expression>
    tools: <expression>
    uses: <expression>
}
```

## Built-in properties

- **`model`**: provider/model binding such as `openai("gpt-4.1-mini")`
- **`instruction`**: string literal or interpolated string sent to the model as the primary prompt
- **`output`**: type expression used to validate the returned JSON value
- **`context`**: reserved property for explicit context wiring (see [Context and Compaction](/advanced/context-sharing))
- **`inference`**: structured generation settings such as temperature and token limits
- **`tools`**: list of tool references such as `tool.search` or `tool.search(query: input.topic)` (legacy inline form)
- **`uses`**: list of tool references bound from MCP server imports, with optional per-agent `max_calls` overrides

## A full example

```wire
agent research_brief {
    model: openai("gpt-4.1-mini")

    inference: {
        temperature: 0.2
        max_tokens: 12_000
    }

    instruction: "Write a concise research brief about {{ input.topic }}."

    output: {
        summary: string
        risks: [string]
        next_steps: [string; 3]
    }
}
```

## References inside agents

Agent expressions can use:

- `input.field`
- `secrets.field`
- `agent.other_agent`
- `agent.other_agent.field`
- `agent.other_agent.nullable_field?.nested_field`
- `dynamic.block_name`
- `dynamic.block_name.field`

Referencing `agent.other_agent` creates a dependency edge automatically.

## Response format

The `output` property supports a response format hint:

```wire
agent structured_writer {
    model: openai("gpt-4.1-mini")
    instruction: "Extract the data from this text."
    output: {
        json_schema: "auto"
        schema: {
            name: string
            age: number
        }
    }
}
```

Accepted values: `auto`, `json_schema`, `json_object`, `instruction_only`.

## Loop form

The grammar supports agent loops:

```wire
agent remediation_plan for finding in agent.findings.items {
    model: openai("gpt-4.1-mini")
    instruction: "Create a remediation plan for {{ finding }}."
    output: string
}
```

Object destructuring is also supported:

```wire
agent process_items for { id, name } in input.items {
    model: openai("gpt-4.1-mini")
    instruction: "Process item {{ id }}: {{ name }}"
    output: string
}
```

## Current runtime behavior

The default runtime executes all agent properties:

- `model`
- `instruction`
- `output`
- `context`
- `inference`
- `tools`
- `uses`

It also fully evaluates `for` loop iteration (with parallel execution per iteration), `context(...)`, `compact(...)`, and `template(...)` function calls.

<Info>
  <code>tool.*</code> references are only executed within the <code>tools:</code>
  property or via <code>uses:</code>. Use the <code>call tool.xxx</code> expression
  in <code>dynamic</code> blocks for tool invocation in other contexts.
</Info>
