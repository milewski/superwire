---
title: Providers
description: Declare model backends and bind agents to them with explicit model calls.
---

Providers are named blocks that hold backend settings.

```ai
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini", "gpt-4.1"]
}
```

## Provider syntax

```ai
provider <provider_name> {
    <property_name>: <expression>
    ...
}
```

Every provider property is a key/value expression pair in the DSL. The parser preserves all properties.

## Binding an agent to a provider

Agents select a provider by calling the provider name in the `model` property.

```ai
agent summarizer {
    model: openai("gpt-4.1-mini")
    prompt: "Summarize the release notes."
    output: string
}
```

The model name can be passed either positionally or as a named argument:

```ai
model: openai("gpt-4.1-mini")
model: openai(model: "gpt-4.1-mini")
```

## Validation behavior

Validation checks these provider-related conditions:

- provider names must be unique
- an agent `model:` call must reference a declared provider
- if a provider declares `models`, the chosen model must appear in that list
- the `model:` property must be a provider call, not a string literal or object

## Built-in runtime provider settings

### OpenAI driver

```ai
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}
```

Required settings consumed by runtime:

- `driver`
- `endpoint`
- `api_key`

Optional setting used by validation:

- `models`

### Ollama driver

```ai
provider ollama {
    driver: "ollama"
    endpoint: "http://localhost:11434"
    models: ["qwen3.5:8b"]
}
```

Required settings consumed by runtime:

- `driver`
- `endpoint` (must include host and port)

Optional setting used by validation:

- `models`

## Practical pattern: local first, cloud second

```ai
provider ollama_local {
    driver: "ollama"
    endpoint: "http://localhost:11434"
    models: ["qwen3.5:8b"]
}

provider openai_cloud {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

agent redact_notes {
    model: ollama_local("qwen3.5:8b")
    prompt: "Remove names and email addresses from {{ input.notes }}."
    output: [string]
}

agent synthesize {
    model: openai_cloud("gpt-4.1-mini")
    prompt: "Summarize {{ agent.redact_notes }} into key insights."
    output: {
        insights: [string]
        recommendations: [string]
    }
}
```

<Tip>
  Provider configuration fields can use string literals or secret references
  (e.g., <code>api_key: secrets.openai_key</code>). The runtime resolves secret
  references in provider <code>endpoint</code> and <code>api_key</code> values.
</Tip>
