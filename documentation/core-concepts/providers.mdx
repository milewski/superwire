## What are Providers?

Providers are the LLM backends that power your agents. Engine AI supports multiple providers, allowing you to use different models for different tasks or switch between providers seamlessly.

## Provider Configuration

Every workflow must define at least one provider:

```ai
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b", "llama2:7b"]
}
```

### Provider Structure

```ai
provider <name> {
    driver <- "<driver_type>"
    config <- { <configuration_options> }
    models <- [<available_models>]
}
```

- **name**: Unique identifier for this provider
- **driver**: The provider type (`ollama`, `openai`, `anthropic`)
- **config**: Provider-specific configuration
- **models**: List of models available through this provider

## Supported Providers

<Tabs>
  <Tab title="Ollama">
    **Ollama** provides local LLM inference with no API costs.

    ```ai
    provider ollama {
        driver <- "ollama"
        config <- { 
            endpoint <- "http://localhost:11434"
        }
        models <- [
            "qwen3:8b",
            "llama2:7b",
            "mistral:7b",
            "codellama:13b"
        ]
    }
    ```

    ### Configuration Options

    | Option | Type | Required | Description |
    |--------|------|----------|-------------|
    | `endpoint` | string | Yes | Ollama server URL |
    | `timeout` | number | No | Request timeout in seconds (default: 300) |
    | `cache_ttl` | number | No | Cache duration in seconds (default: 0) |

    ### Using Ollama Models

    ```ai
    agent task {
        model <- "ollama/qwen3:8b"
        prompt <- "Your prompt here"
    }
    ```

    <Tip>
      Ollama is perfect for development and testing. Install models with `ollama pull <model>`.
    </Tip>
  </Tab>

  <Tab title="OpenAI">
    **OpenAI** provides access to GPT models via API.

    ```ai
    provider openai {
        driver <- "openai"
        config <- { 
            api_key <- env("OPENAI_API_KEY")
            organization <- env("OPENAI_ORG_ID")  // Optional
        }
        models <- [
            "gpt-4",
            "gpt-4-turbo",
            "gpt-3.5-turbo"
        ]
    }
    ```

    ### Configuration Options

    | Option | Type | Required | Description |
    |--------|------|----------|-------------|
    | `api_key` | string | Yes | OpenAI API key |
    | `organization` | string | No | Organization ID |
    | `base_url` | string | No | Custom API endpoint |
    | `timeout` | number | No | Request timeout in seconds |
    | `max_retries` | number | No | Maximum retry attempts (default: 3) |

    ### Using OpenAI Models

    ```ai
    agent task {
        model <- "openai/gpt-4"
        prompt <- "Your prompt here"
    }
    ```

    <Warning>
      Store API keys in environment variables, never hardcode them in workflow files.
    </Warning>
  </Tab>

## Multiple Providers

You can define multiple providers in a single workflow:

```ai
// Local provider for development
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

// Cloud provider for production
provider openai {
    driver <- "openai"
    config <- { api_key <- env("OPENAI_API_KEY") }
    models <- ["gpt-4"]
}

// Use different providers for different agents
agent draft {
    model <- "ollama/qwen3:8b"  // Fast local model for drafts
    prompt <- "Create a draft"
}

agent refine {
    model <- "openai/gpt-4"  // Powerful cloud model for refinement
    prompt <- "Refine this draft: {{ draft.text }}"
}
```

<Info>
  Using multiple providers lets you optimize for cost, speed, and quality based on each agent's requirements.
</Info>

## Environment Variables

Use `env()` to access environment variables:

```ai
provider openai {
    driver <- "openai"
    config <- { 
        api_key <- env("OPENAI_API_KEY")
        organization <- env("OPENAI_ORG_ID")
    }
    models <- ["gpt-4"]
}
```

Set environment variables before running:

```bash
export OPENAI_API_KEY="sk-..."
export OPENAI_ORG_ID="org-..."
engine-ai run workflow.ai
```

## Model Selection

### Specifying Models

Reference models using the format `provider/model`:

```ai
agent task {
    model <- "ollama/qwen3:8b"
    //        ^^^^^^  ^^^^^^^^
    //        |       |
    //        |       +-- Model name
    //        +---------- Provider name
    prompt <- "Your prompt"
}
```

### Model Availability

Models must be declared in the provider's `models` list:

```ai
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]  // Only this model is available
}

agent valid {
    model <- "ollama/qwen3:8b"  // ✓ Valid
    prompt <- "Task"
}

agent invalid {
    model <- "ollama/llama2:7b"  // ✗ Error: model not in provider's list
    prompt <- "Task"
}
```

## Provider Caching

Enable caching to avoid redundant API calls:

```ai
provider ollama {
    driver <- "ollama"
    config <- { 
        endpoint <- "http://localhost:11434"
        cache_ttl <- 3600  // Cache responses for 1 hour
    }
    models <- ["qwen3:8b"]
}
```

### How Caching Works

1. **Cache Key**: Generated from model, prompt, and parameters
2. **Cache Hit**: Return cached response if available and not expired
3. **Cache Miss**: Call provider API and cache the response
4. **Expiration**: Cached responses expire after `cache_ttl` seconds

<Warning>
  Caching is based on exact prompt matching. Small changes to prompts result in cache misses.
</Warning>

## Advanced Configuration

### Custom Endpoints

Use custom API endpoints for self-hosted or proxy services:

```ai
provider openai {
    driver <- "openai"
    config <- { 
        api_key <- env("OPENAI_API_KEY")
        base_url <- "https://custom-proxy.example.com/v1"
    }
    models <- ["gpt-4"]
}
```

### Timeouts and Retries

Configure timeout and retry behavior:

```ai
provider openai {
    driver <- "openai"
    config <- { 
        api_key <- env("OPENAI_API_KEY")
        timeout <- 60  // 60 second timeout
        max_retries <- 5  // Retry up to 5 times
    }
    models <- ["gpt-4"]
}
```

### Request Parameters

Pass additional parameters to the provider:

```ai
provider ollama {
    driver <- "ollama"
    config <- { 
        endpoint <- "http://localhost:11434"
        temperature <- 0.7
        top_p <- 0.9
        max_tokens <- 2000
    }
    models <- ["qwen3:8b"]
}
```

## Examples

### Development Setup

```ai
// Use local Ollama for fast iteration
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

agent test {
    model <- "ollama/qwen3:8b"
    prompt <- "Test prompt"
}
```

### Production Setup

```ai
// Use OpenAI with fallback to Anthropic
provider openai {
    driver <- "openai"
    config <- { 
        api_key <- env("OPENAI_API_KEY")
        timeout <- 30
        max_retries <- 3
    }
    models <- ["gpt-4", "gpt-3.5-turbo"]
}

provider anthropic {
    driver <- "anthropic"
    config <- { 
        api_key <- env("ANTHROPIC_API_KEY")
        timeout <- 30
        max_retries <- 3
    }
    models <- ["claude-3-opus-20240229"]
}

agent primary {
    model <- "openai/gpt-4"
    prompt <- "Primary task"
}

agent fallback {
    model <- "anthropic/claude-3-opus-20240229"
    prompt <- "Fallback task"
}
```

### Hybrid Setup

```ai
// Use local for simple tasks, cloud for complex ones
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

provider openai {
    driver <- "openai"
    config <- { api_key <- env("OPENAI_API_KEY") }
    models <- ["gpt-4"]
}

agent simple_task {
    model <- "ollama/qwen3:8b"  // Fast and free
    prompt <- "Simple classification"
}

agent complex_task {
    model <- "openai/gpt-4"  // Powerful but costs money
    prompt <- "Complex reasoning task"
}
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Provider connection failed">
    **Ollama:**
    ```bash
    # Check if Ollama is running
    curl http://localhost:11434/api/tags
    
    # Start Ollama if not running
    ollama serve
    ```

    **OpenAI/Anthropic:**
    ```bash
    # Verify API key is set
    echo $OPENAI_API_KEY
    
    # Test API connection
    curl https://api.openai.com/v1/models \
      -H "Authorization: Bearer $OPENAI_API_KEY"
    ```
  </Accordion>

  <Accordion title="Model not found">
    Ensure the model is:
    1. Listed in the provider's `models` array
    2. Available on the provider (for Ollama: `ollama list`)
    3. Spelled correctly with proper casing
  </Accordion>

  <Accordion title="API rate limits">
    Configure retries and backoff:
    ```ai
    provider openai {
        driver <- "openai"
        config <- { 
            api_key <- env("OPENAI_API_KEY")
            max_retries <- 5
            retry_delay <- 2  // Seconds between retries
        }
        models <- ["gpt-4"]
    }
    ```
  </Accordion>

  <Accordion title="Timeout errors">
    Increase timeout for slow models:
    ```ai
    provider ollama {
        driver <- "ollama"
        config <- { 
            endpoint <- "http://localhost:11434"
            timeout <- 600  // 10 minutes
        }
        models <- ["large-model:70b"]
    }
    ```
  </Accordion>
</AccordionGroup>
