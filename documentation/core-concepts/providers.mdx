---
title: Providers
description: Configure model providers and model aliases.
---

Providers define how agents reach a model backend. In most deployments the workflow reads provider settings from `secrets` so the same `.wire` file can run in development, staging, and production.

## OpenAI-compatible provider

```wire
secrets {
    endpoint: string
    api_key: string
    models: {
        flash: string
        pro: string
        max: string
    }
}

provider ai {
    driver: "openai"
    endpoint: secrets.endpoint
    api_key: secrets.api_key
    models: {
        flash: secrets.models.flash
        pro: secrets.models.pro
        max: secrets.models.max
    }
}
```

The executor payload supplies the actual values:

```json
{
  "secrets": {
    "endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "api_key": "YOUR_API_KEY",
    "models": {
      "flash": "qwen3.6-plus",
      "pro": "qwen3.6-plus",
      "max": "qwen3.6-plus"
    }
  }
}
```

## Model selection

Agents choose a model alias from the provider:

```wire
agent draft {
    model: ai("flash")
    instruction: "Draft a short answer."
    output: {
        answer: string
    }
}

agent review {
    model: ai("pro")
    instruction: "Review the draft: {{ agent.draft.answer }}"
    output: {
        approved: boolean
        notes: [string]
    }
}
```

## Model options

Model-specific execution options can be attached to the model binding:

```wire
agent careful_review {
    model: ai("pro") {
        temperature: 0.2
        max_tokens: 1200
    }
    instruction: "Review carefully and return structured notes."
    output: {
        notes: [string]
    }
}
```

Use aliases such as `flash`, `pro`, and `max` to keep workflow intent stable while changing concrete model names through secrets.
