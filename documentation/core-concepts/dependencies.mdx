title: Dependencies
description: Engine AI builds the execution graph from agent references automatically.
---

Engine AI does not require you to list edges manually. Dependencies come from references.

## Dependency rule

If an agent expression references another agent through `agent.<name>`, the current agent depends on that upstream agent.

```txt
agent first {
    model: scripted("mock-model")
    prompt: "First prompt: {{ input.subject }}"
    output: {
        summary: string
    }
}

agent second {
    model: scripted("mock-model")
    prompt: "Second prompt: {{ agent.first.summary }}"
    output: string
}
```

In this case, `second` runs after `first`.

## Where dependencies are discovered

The dependency graph is built from references found in:

- `model`
- `prompt`
- `context`
- `inference`
- `tools`
- custom agent properties
- loop iterables in `agent ... for ... in ...`

## What does not create dependencies

- references to `input.*`
- references to `secrets.*`
- literal values

## Cycle detection

Validation rejects cycles before runtime execution.

```txt
agent alpha {
    model: openai("gpt-4.1-mini")
    prompt: "Use {{ agent.beta }}"
    output: string
}

agent beta {
    model: openai("gpt-4.1-mini")
    prompt: "Use {{ agent.alpha }}"
    output: string
}
```

This produces an `AgentDependencyCycle` validation problem.

## Practical guidance

- reference full upstream objects when the downstream step truly needs them
- reference fields when the downstream step only needs a small part of the result
- keep dependency chains shallow when you want more parallelism
- use explicit `output` blocks to keep public results stable
