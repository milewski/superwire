---
title: Schemas
description: Define reusable output types with arrays, unions, tuples, enums, and inline descriptions.
---

Schemas let you name complex type expressions and reuse them in agent outputs, input fields, and other schemas.

## Named schemas

```txt
schema Participant {
    name: string
    role: string
}

schema ResearchSummary {
    title: string
    lead: schema.Participant
    participants: [schema.Participant]
}
```

## Where schemas can be used

- inside another schema
- inside `input`
- inside `secrets`
- as an agent `output`

```txt
input {
    lead_participant: schema.Participant
    previous_summary: schema.ResearchSummary
}

agent summarize {
    model: ollama("qwen3.5:32b")
    prompt: "Summarize the provided research context."
    output: schema.ResearchSummary
}
```

## Field descriptions

A typed field may optionally include a trailing string description.

```txt
schema ReleaseNote {
    title: string "Short human-readable title"
    impact: "low" | "medium" | "high" "Severity bucket"
}
```

The parser stores these descriptions in the AST so schema-aware tooling can use them.

## Supported type forms

- primitive scalars: `string`, `number`, `float`, `boolean`, `null`
- schema references: `schema.Name`
- arrays: `[string]`
- fixed-length arrays: `[string; 3]`
- tuples: `(string, number, [string; 3])`
- objects: `{ title: string score: number }`
- unions: `string | null`
- string enums: `"draft" | "ready" | "published"`

## Practical example

```txt
schema AllTypes {
    string_value: string
    nullable_string: string | null
    fixed_array: [string; 3]
    tuple_value: (string, number, [string; 3])
    object_value: {
        name: string
        score: number
    }
    enum_value: "draft" | "ready" | "published"
}
```

## Validation rules

Validation checks that every `schema.Name` reference points to a declared schema. Unknown schema references are reported with source spans.
