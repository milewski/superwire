A workflow is a sequence of declarations. The grammar currently supports these top-level declaration kinds:

- `provider` — model backend configuration
- `mcp` — MCP server connection settings
- `secrets` — sensitive runtime values
- `input` — regular runtime values
- `schema` — reusable named types
- `tool` — tool definitions (inline or imported from MCP)
- `resource` — resource imports from MCP servers
- `prompt` — prompt imports from MCP servers
- `dynamic` — runtime-computed values via tool calls and MCP
- `agent` — model calls with instructions and output types
- `output` — the final JSON object returned by the workflow

```wire
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

secrets {
    openai_api_key: string
}

input {
    topic: string
}

schema Brief {
    title: string
    bullets: [string; 3]
}

agent write_brief {
    model: openai("gpt-4.1-mini")
    instruction: "Write a short brief about {{ input.topic }}."
    output: schema.Brief
}

output {
    brief: agent.write_brief
}
```

## Mental model

- **Providers** describe model backends and backend-specific settings.
- **MCP servers** describe connections to external tool/resource/prompt providers.
- **Input** describes non-secret values passed in at execution time.
- **Secrets** describes sensitive values passed in separately from normal input.
- **Schemas** define reusable named types.
- **Tools** define function-like operations that agents can call.
- **Agents** define model calls and references to prior state.
- **Dynamic blocks** compute values at runtime through tool calls or MCP operations.
- **Output** shapes the final JSON document returned by the workflow.

## Declaration ordering

The parser accepts declarations in any order, and validation resolves references by name.

<Tip>
  Even though the language does not require a strict order, most teams keep
  providers, secrets, input, schemas, and MCP declarations near the top, then tools, dynamic blocks, and agents, then the final <code>output</code> block.
</Tip>

## What creates dependencies

Agent dependencies are inferred from references such as `agent.summary` or `agent.summary.title`.

- Referencing `input.*` does **not** create an agent dependency.
- Referencing `agent.*` **does** create an agent dependency.
- Referencing `dynamic.*` **does** create a dependency on the dynamic block.
- Referencing `tool.*` creates a dependency when used in `uses:` or dynamic blocks.
- Validation detects circular dependencies before execution.
