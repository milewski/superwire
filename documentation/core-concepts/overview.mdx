title: Overview
description: The core ideas behind Superwire workflows.
---

A Superwire workflow is a dependency graph written as declarations. Each declaration gives the runtime enough information to validate the graph and execute only what is needed.

## Top-level declarations

```wire
secrets {
    endpoint: string
    api_key: string
    models: {
        flash: string
        pro: string
        max: string
    }
}

input {
    topic: string
}

provider ai {
    driver: "openai"
    endpoint: secrets.endpoint
    api_key: secrets.api_key
    models: {
        flash: secrets.models.flash
        pro: secrets.models.pro
        max: secrets.models.max
    }
}

agent summarize {
    model: ai("flash")
    instruction: "Summarize {{ input.topic }}."
    output: {
        title: string
        summary: string
    }
}

output {
    title: agent.summarize.title
    summary: agent.summarize.summary
}
```

## How execution works

1. The executor decodes `workflow_source_base64`.
2. The parser builds a workflow AST.
3. The validator checks declarations, references, schemas, and dependency cycles.
4. The runtime builds the dependency graph.
5. Agents and dynamic values execute in dependency order.
6. The final `output` block is returned as JSON.

## Design principles

- **Explicit inputs**: callers know exactly which fields to send.
- **Isolated secrets**: provider keys and internal endpoints are passed separately.
- **Typed outputs**: every agent declares a structured output contract.
- **Composable graph**: references such as `agent.plan.steps` define dependencies automatically.
- **Tool-aware**: agents can use imported MCP tools only when declared in `uses:`.
