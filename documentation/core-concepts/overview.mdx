A workflow is a sequence of declarations. The grammar currently supports six top-level declaration kinds:

- `provider`
- `secrets`
- `input`
- `schema`
- `agent`
- `output`

```ai-dsl
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

secrets {
    openai_api_key: string
}

input {
    topic: string
}

schema Brief {
    title: string
    bullets: [string; 3]
}

agent write_brief {
    model: openai("gpt-4.1-mini")
    prompt: "Write a short brief about {{ input.topic }}."
    output: schema.Brief
}

output {
    brief: agent.write_brief
}
```

## Mental model

- **Providers** describe model backends and backend-specific settings.
- **Input** describes non-secret values passed in at execution time.
- **Secrets** describes sensitive values passed in separately from normal input.
- **Schemas** define reusable named types.
- **Agents** define model calls and references to prior state.
- **Output** shapes the final JSON document returned by the workflow.

## Declaration ordering

The parser accepts declarations in any order, and validation resolves references by name.

<Tip>
  Even though the language does not require a strict order, most teams keep
  providers, secrets, input, and schemas near the top, then agents, then the
  final `output` block.
</Tip>

## What creates dependencies

Agent dependencies are inferred from references such as `agent.summary` or `agent.summary.text`.

- Referencing `input.*` does **not** create an agent dependency.
- Referencing `agent.*` **does** create an agent dependency.
- Validation detects circular dependencies before execution.
