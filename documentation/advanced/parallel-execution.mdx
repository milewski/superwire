Engine AI computes execution order from agent references.

## Automatic parallelism

Two agents can run in parallel when neither depends on the other.

```txt
agent sentiment {
    model: openai("gpt-4.1-mini")
    prompt: "Classify sentiment for {{ input.text }}"
    output: string
}

agent topics {
    model: openai("gpt-4.1-mini")
    prompt: "Extract topics from {{ input.text }}"
    output: [string]
}
```

Because both agents depend only on `input.text`, they can be scheduled independently.

## Serial execution by reference

```txt
agent summary {
    model: openai("gpt-4.1-mini")
    prompt: "Summarize {{ input.text }}"
    output: string
}

agent review {
    model: openai("gpt-4.1-mini")
    prompt: "Review this summary: {{ agent.summary }}"
    output: string
}
```

`review` waits for `summary` because its prompt references `agent.summary`.

## Loop syntax and intended behavior

The grammar also supports looped agents:

```txt
agent remediation_plan for finding in agent.findings.items {
    model: openai("gpt-4.1-mini")
    prompt: "Create a remediation plan for {{ finding }}"
    output: {
        title: string
        steps: [string]
    }
}
```

This syntax is designed to produce one agent run per item and return an array of outputs.

<Warning>
  The current default runtime does not execute looped agents yet and returns
  `UnsupportedForLoop`. The parser and validator still understand the syntax.
</Warning>

## Performance guidance

- keep agents independent unless downstream steps truly need upstream data
- reference only the fields you need from previous agents
- break wide fan-out workflows into stable, typed stages
- declare `output` types so failures surface early
