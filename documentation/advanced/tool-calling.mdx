---
title: Tool Calling
description: Reference the grammar for `tools:` and `tool.*` expressions, including named arguments.
---

Tools are expressed through the `tools:` agent property.

## Basic syntax

```ai
agent assistant_with_tools {
    model: openai("gpt-4.1-mini")
    tools: [
        tool.web_search,
        tool.knowledge_base_search(password: secrets.knowledge_base_password),
        tool.issue_tracker_lookup(project: "engine-ai", status: "open", token: secrets.issue_tracker_token)
    ]
    prompt: "Answer the question using tools when needed: {{ input.question }}"
    output: {
        answer: string
        sources: [string]
    }
}
```

## Supported expression shapes in the grammar

- bare tool reference: `tool.web_search`
- tool call with named arguments: `tool.search(query: input.query)`
- tool arguments built from literals, references, arrays, and objects

## Validation behavior

- `tool` is a reserved keyword root in references
- tool expressions still participate in dependency scanning
- secret references are allowed inside `tools:` because they are configuration data, not prompt text

## Runtime behavior

The `tools:` property is fully evaluated at runtime. Tool references within `tools:` are resolved, bound with their named arguments, and passed to the agent executor. Tools must be registered with the runtime via `registered_runtime_tools()` on the `LoopAgentRunner`.

<Warning>
  `tool.*` references are only executed within the `tools:` property. Using
  `tool.*` in general expressions (such as prompts, output, or interpolation)
  returns `UnsupportedFeature` at runtime.
</Warning>

## Practical guidance

- keep tool argument payloads small and explicit
- prefer named arguments for readability
- pass secrets only through tool configuration, never through prompts
