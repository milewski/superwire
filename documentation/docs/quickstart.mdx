This guide uses one source of truth for every execution surface.

## 1. Start the executor

```bash
docker run --rm -p 13703:13703 rmilewski/superwire:latest
```

Open `http://localhost:13703/playground` to confirm the process is reachable. There is currently no dedicated health route.

## 2. Save `hello.wire`

<HelloWorkflow />

The workflow accepts `input.name` and `secrets.api_key`. The final workflow object has the type `{ message: string }`.

Export a development key without placing it in the workflow:

```bash
export OPENAI_API_KEY="replace-at-runtime"
```

Do not commit the value or paste a production key into an untrusted browser.

## 3. Choose a run path

<Tabs>
  <Tab title="Playground">
    1. Open `http://localhost:13703/playground`.
    2. Replace the editor content with `hello.wire`.
    3. Set Input JSON to `{ "name": "Ada" }`.
    4. Set Secrets JSON to `{ "api_key": "replace-at-runtime" }`.
    5. Select **Validate**, then **Run**.

    <Warning>
      The Playground persists workflow source, Input JSON, tab/active-tab state, cache settings, and theme in browser local storage. It does not persist Secrets JSON, output, graph data, or event history; secrets remain in page memory until reload. **Copy with secrets** writes the current input and secrets into a portable bundle on the system clipboard, so use only development credentials on a trusted browser.
    </Warning>
  </Tab>
  <Tab title="CLI">
    Build the native CLI or use the binary included in the image. Store the secret in a mode-restricted temporary file so it is not copied into shell history:

    ```bash
    umask 077
    printf '{"api_key":"%s"}\n' "$OPENAI_API_KEY" > hello.secrets.json

    superwire-cli workflow check hello.wire
    superwire-cli workflow run hello.wire \
      --input-json '{"name":"Ada"}' \
      --secrets-file hello.secrets.json \
      --pretty

    rm hello.secrets.json
    ```

    The CLI prints the final workflow object directly:

    ```json
    {
      "message": "Hello Ada — welcome to Superwire."
    }
    ```
  </Tab>
  <Tab title="HTTP Linux">
    GNU `base64` uses `-w 0`:

    ```bash
    WORKFLOW_SOURCE_BASE64="$(base64 -w 0 hello.wire)"

    curl --fail-with-body --silent http://localhost:13703/execute \
      -H 'Content-Type: application/json' \
      -d @- <<JSON
    {
      "workflow_source_base64": "$WORKFLOW_SOURCE_BASE64",
      "input": {"name": "Ada"},
      "secrets": {"api_key": "$OPENAI_API_KEY"}
    }
    JSON
    ```
  </Tab>
  <Tab title="HTTP macOS">
    macOS `base64` wraps differently:

    ```bash
    WORKFLOW_SOURCE_BASE64="$(base64 < hello.wire | tr -d '\n')"

    curl --fail-with-body --silent http://localhost:13703/execute \
      -H 'Content-Type: application/json' \
      -d @- <<JSON
    {
      "workflow_source_base64": "$WORKFLOW_SOURCE_BASE64",
      "input": {"name": "Ada"},
      "secrets": {"api_key": "$OPENAI_API_KEY"}
    }
    JSON
    ```
  </Tab>
  <Tab title="HTTP PowerShell">
    ```powershell
    $workflowSourceBase64 = [Convert]::ToBase64String(
        [IO.File]::ReadAllBytes((Resolve-Path .\hello.wire))
    )

    $requestBody = @{
        workflow_source_base64 = $workflowSourceBase64
        input = @{ name = "Ada" }
        secrets = @{ api_key = $env:OPENAI_API_KEY }
    } | ConvertTo-Json -Depth 5

    Invoke-RestMethod `
        -Method Post `
        -Uri http://localhost:13703/execute `
        -ContentType application/json `
        -Body $requestBody
    ```
  </Tab>
</Tabs>

HTTP JSON wraps the final object:

```json
{
  "output": {
    "message": "Hello Ada — welcome to Superwire."
  }
}
```

The model chooses the wording; only the output shape is stable.

## 4. Validate and format

The CLI checks source without making a model request:

```bash
superwire-cli workflow check hello.wire
superwire-cli fmt hello.wire
```

The executor also exposes `POST /validate` and `POST /format`. See [Executor API](/api-reference/executor-api).

## 5. Stream progress

Set `Accept: text/event-stream` to receive lifecycle events. The terminal success event is `workflow_completed`, and its final value is nested at `data.output` inside the serialized event envelope.

See [Streaming and events](/api-reference/streaming-events) for reconnect and cancellation.
