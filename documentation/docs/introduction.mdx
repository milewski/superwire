Superwire is a declarative DSL for controlled server-side AI workflows. A `.wire` file defines:

- public `input` and sensitive `secrets` supplied at runtime;
- provider connections and reusable model profiles;
- typed schemas and object-shaped agent outputs;
- explicit dependencies between dynamic values and agents;
- MCP tools, prompts, and resources available to each step;
- one final structured `output` consumed by the application.

The surrounding application still owns authorization, transactions, rate limits, audit logs, and human approval. Superwire owns the AI workflow contract inside those boundaries.

## The smallest useful mental model

```text
runtime values -> provider/model -> typed agent -> final output
```

Use the [checked hello workflow](/examples/basic-agent) to see all four pieces together.

## Choose an execution surface

| Surface | Best for | Result shape |
| --- | --- | --- |
| [Playground](/playground) | visual evaluation and workflow authoring | displays the final workflow object |
| [CLI](/cli) | local development and automation | prints the final workflow object directly |
| [HTTP JSON](/quickstart) | backend integration | wraps the final value as `{ "output": ... }` |
| [HTTP SSE](/api-reference/streaming-events) | progress, reconnect, and cancellation | final value at `event.data.output` |
| [Laravel](/integrations/laravel) | PHP/Laravel applications | final value at `$result->output` |

## What type safety means

Superwire parses and semantically validates source before execution. It verifies declarations, references, schema paths, dependencies, tool scopes, and runtime input/secret shapes. Agent output is validated at runtime against its declared object shape.

This is preflight and runtime validation, not Rust-style compilation of a workflow into a binary. Provider behavior and model content remain nondeterministic.
