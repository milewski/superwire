## Use lowercase snake_case

```wire
schema task_summary {
    summary: string
}

model fast from llm {
    id: "model-id"
}

agent summarize_task {
    model: model.fast
    instruction: "Summarize {{ input.task_id }}."

    output {
        summary: string
    }
}
```

Providers, models, schemas, agents, capabilities, and fields use descriptive lowercase snake_case names. Avoid names that only encode a vendor/model version when the profile's role is clearer.

## Order declarations for readers

A practical order is:

1. `input` and `secrets`;
2. providers and models;
3. schemas;
4. MCP servers/imports;
5. global dynamic values;
6. agents;
7. final output.

The executor derives dependency order from references; source order is for maintainers.

## Format with the CLI

```bash
superwire-cli fmt workflow.wire
superwire-cli workflow check workflow.wire
```

Do not hand-align blocks against the canonical formatter.

## Use comments intentionally

```wire
// Runtime credentials are supplied by the caller.
secrets {
    api_key: string
}

schema release_note {
    /// Short title displayed to the user.
    title: string
}
```

`//` explains source. `///` describes a typed field for schema-aware tooling/model output.

## Keep complete examples checked

Documentation pages import complete workflows from `examples/wire` snippets. Small syntax-reference blocks may show a fragment, but they should contain real syntax and never placeholder ellipses inside a `wire` fence.
