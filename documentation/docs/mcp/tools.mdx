## Declaration properties

| Property | Purpose |
| --- | --- |
| `description` | Local tool description exposed to model/tooling. |
| `max_calls` | Workflow import call budget. |
| `input {}` | Model-visible or call-supplied input fields. |
| `bindings {}` | Trusted values supplied by workflow expressions. |
| `output {}` | Expected output schema override. |

Remote MCP schema discovery supplies fields when local blocks are omitted. Discovery preserves unions, nullable array items, formats, constraints, and `additionalProperties` instead of flattening them. Local schemas let a workflow narrow/override the imported contract.

## Input versus bindings

```wire
tool search_tasks from mcp.tasks.tool.search_tasks {
    max_calls: 4

    input {
        query: string
    }

    bindings {
        workspace_id: input.workspace_id
    }

    output {
        ids: [number]
    }
}
```

`query` is visible to a model or must be supplied by a deterministic call. `workspace_id` is fixed by trusted workflow data and is not delegated to the model.

## Workflow-owned call

```wire
dynamic {
    search: call tool.search_tasks {
        input {
            query: input.query
        }

        max_calls: 1
    }
}
```

Use workflow ownership when the operation must happen at a declared point. Call-time `bindings` can override/add trusted binding values when the imported contract permits them.

## Model-owned access

```wire
agent researcher {
    model: model.fast
    uses: [
        tool.search_tasks {
            max_calls: 2
        },
    ]
    instruction: "Research {{ input.topic }}."

    output {
        findings: [string]
    }
}
```

Use model ownership when the model must decide whether or how to call. Tools absent from `uses` are unavailable to that agent.

`max_calls` can be declared on an imported tool, batch import, deterministic call, and an agent `uses` entry. Narrow budgets near the use site; do not rely on prompts alone to limit calls.

## Validation and errors

The runtime validates fixed declaration bindings and merged call-time bindings before dispatch. It validates the returned value against the tool output schema at the tool boundary.

For model-owned calls, schema/input/output failures are returned to the model as structured, recoverable tool errors so it can correct a call within the configured budget. Workflow-owned calls surface the same contract failure to workflow execution. SSE exposes schema-fetch, validation, MCP-call, and model tool-call lifecycle metadata, not argument values, schemas, or returned payloads. See [Streaming and events](/api-reference/streaming-events).

## Lock before deployment

Use [MCP lockfiles](/mcp/lockfiles) to resolve and review remote metadata. Domain authorization, idempotency, and transaction safety still belong in the MCP tool implementation.
