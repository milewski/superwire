## OpenAI driver

<HelloWorkflow />

The `openai` driver defaults to `https://api.openai.com/v1` and reads `OPENAI_API_KEY` when `api_key` is omitted. The checked workflow instead requires a typed runtime secret so each caller can supply it.

## Compatible gateway

```wire
secrets {
    api_key: string
}

provider gateway from openai_compatible {
    endpoint: "https://gateway.example.test/v1"
    api_key: secrets.api_key
}

model fast from gateway {
    id: "gateway-model-id"
    wire_api: "chat/completion"
}
```

`openai_compatible` has no environment-key fallback; supply `api_key` when the gateway requires one.

## API mode

Models default to:

```wire
wire_api: "responses"
```

Select:

```wire
wire_api: "chat/completion"
```

when the backend implements Chat Completions rather than Responses, or when an agent uses `file`. Compatibility is feature-specific: confirm structured output, tool calls, assets, streaming, and file endpoints with the chosen backend.

See the [Provider matrix](/integrations/providers) for OpenAI, Ollama, Mistral, Groq, DeepSeek, xAI, Together, Fireworks, Perplexity, Cerebras, OpenRouter, Cohere, SambaNova, Anthropic, and Google drivers.
