A provider declaration names a runtime driver. `endpoint` and `api_key` are the only provider properties. If omitted, the runtime uses the driver's default endpoint and supported environment variables.

## Runtime secret binding

Use a typed secret when the caller supplies the credential:

```wire
secrets {
    api_key: string
}

provider primary from anthropic {
    api_key: secrets.api_key
}
```

Use environment fallback when the executor owns one deployment credential:

```wire
provider primary from anthropic {
}
```

The second form reads `ANTHROPIC_API_KEY` or `ANTHROPIC_KEY` from the executor environment. Do not pass provider keys through model instructions.

## Model wire API

Models default to the Responses API mode:

```wire
model fast from primary {
    id: "gpt-4.1-mini"
}
```

Choose Chat Completions explicitly when the backend or feature requires it:

```wire
model files from primary {
    id: "gpt-4.1-mini"
    wire_api: "chat/completion"
}
```

Allowed values are `"responses"` and `"chat/completion"`. Agent `file` directives require `"chat/completion"`.

## Model assets

Declare non-text asset kinds the model accepts:

```wire
model vision from primary {
    id: "vision-model"
    assets: ["image", "video", "document"]
}
```

Superwire validates `asset` usage against this list before the provider call.

## Provider retries

Provider retry settings live in model inference configuration:

```wire
model resilient from primary {
    id: "gpt-4.1-mini"

    inference {
        provider_max_retries: 3
        provider_retry_base_delay_ms: 1000
    }
}
```

Defaults are three retries and a 1,000 ms base delay. `provider_max_retries` is capped at 8; base and per-attempt delays are capped at 60,000 ms. Backoff doubles from the base with checked arithmetic. A provider `Retry-After` value overrides calculated backoff but is also capped at 60 seconds.

Retries apply to HTTP 408, 425, 429, 5xx, connection/time-out/transport/I/O failures. Authentication, permission, tool, context-overflow, configuration, MCP, JSON/validation, cancellation, and other permanent failures are not retried.

SSE emits `provider_attempt_started`, `provider_attempt_completed`, and `provider_attempt_failed`. Exhaustion produces `provider_retries_exhausted` with the final provider diagnostic in `cause`; applications should use its retryability/status rather than adding an unbounded outer retry loop.

## Docker-hosted providers

When the executor runs in Docker, its `localhost` is not the host. For host Ollama, expose `host.docker.internal` as described in [Installation](/installation#docker-networking), then override the endpoint.
