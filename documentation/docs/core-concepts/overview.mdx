## Declaration map

| Declaration | Contract |
| --- | --- |
| `input` | Public runtime values supplied by the caller. |
| `secrets` | Sensitive runtime values supplied by the caller. |
| `provider` | Named connection using one of the supported provider drivers. |
| `model` | Reusable provider-specific model identity, API mode, assets, and inference defaults. |
| `schema` | Reusable object or variant type. |
| `mcp` | MCP server endpoint and headers. |
| `tool`, `prompt`, `resource` | Imported, scoped MCP capabilities. |
| `dynamic` | Global or agent-local computed values. |
| `agent` | One model step with explicit model, instruction, capability/context scope, and object output. |
| `output` | Final application-shaped value. |

## Type boundary

The runtime validates:

1. source syntax and declarations;
2. references, schemas, capabilities, and dependency cycles;
3. runtime input/secrets and provider/MCP configuration;
4. tool and model output against declared shapes.

Model content remains variable. Downstream code can rely on the declared JSON shape, not exact wording.

## Dependency graph

References create execution edges. An agent using `agent.research.facts` waits for `research`; independent agents may run concurrently. Tool calls and dynamic values can also create upstream dependencies.

```text
input/secrets -> dynamic/tool work -> agent(s) -> output
```
