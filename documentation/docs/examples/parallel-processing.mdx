## Independent agents

<ParallelWorkflow />

`risks` and `actions` have no dependency relationship and may run concurrently. `plan` waits for both because its instruction references both outputs.

## Looped agent

<LoopWorkflow />

The loop destructures each typed input object. Its final `agent.analyze` value is an array of output objects in input order.

HTTP execution defaults `options.max_concurrency` to `5`. Set it lower to limit simultaneous provider/tool work; the runtime uses an effective lower bound of one.
