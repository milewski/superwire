Superwire is a declarative language for describing agent workflows.
A workflow is a plain text file (`.wire`) made from a small set of declarations:

- **providers**, which define where models come from and how to reach them
- **input**, which defines typed values passed in at execution time
- **secrets**, which define sensitive values passed in separately from normal input
- **schemas**, which define reusable named output types
- **agents**, which define model calls, references, and behavior
- **output**, which shapes the final JSON object returned by the workflow
- **dynamic** blocks, which compute values at runtime through tool calls and MCP integrations
- **MCP** declarations, which connect to external tools, resources, and prompts

```wire
provider ollama {
    driver: "ollama"
    endpoint: "http://localhost:11434"
    models: ["qwen3.5:32b"]
}

agent greeting {
    model: ollama("qwen3.5:32b")
    instruction: "Write a short welcome message."
    output: string
}

output {
    greeting: agent.greeting
}
```

## What the stack does today

Superwire has three useful layers:

1. **Parser**: converts workflow text into a typed AST.
2. **Validator**: checks names, schema references, dependency cycles, secret leaks, and reference paths.
3. **Runtime**: executes validated workflows with built-in OpenAI and Ollama drivers, MCP tool/resource/prompt integrations, and deterministic tool support.

<Info>
  The runtime executes all agent properties: <code>model</code>,
  <code>instruction</code>, <code>output</code>, <code>context</code>,
  <code>inference</code>, <code>tools</code>, and <code>uses</code>.
  Built-in functions <code>context(...)</code>, <code>compact(...)</code>,
  and <code>template(...)</code> are also evaluated. Agent <code>for</code>
  loops run iterations in parallel. <code>tool.*</code> references are
  resolved through the MCP tool and batch import system. Dynamic blocks
  compute values at runtime through tool calls and MCP integrations.
</Info>

## Why this DSL is useful

- **Readable**: workflows stay close to the business problem.
- **Typed**: schemas, arrays, tuples, enums, and variants are first-class.
- **Composable**: agent references form a dependency graph automatically.
- **Safe**: validation blocks leaked secrets and invalid reference paths early.
- **Extensible**: MCP integrations bring in tools, resources, and prompts from external servers.
- **Embeddable**: the Rust API supports parse-only, validate-only, and execution flows.

## A more complete example

```wire
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

input {
    product_name: string
    audience: string
}

agent release_summary {
    model: openai("gpt-4.1-mini")
    instruction: "Summarize {{ input.product_name }} for {{ input.audience }}."
    output: {
        summary: string
        key_points: [string; 3]
    }
}

output {
    product_name: input.product_name
    summary: agent.release_summary.summary
    key_points: agent.release_summary.key_points
}
```

## The `instruction` property

You may notice that agents use **`instruction:`** rather than `prompt:`. This is the canonical property name in the DSL. It defines the text sent to the LLM as the primary instruction.
