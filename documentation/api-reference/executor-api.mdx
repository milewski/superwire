---
title: Executor API
description: HTTP contract for /execute and /execute/stream.
---

The Docker executor exposes two endpoints with the same request body:

- `POST /execute` returns the completed workflow output as JSON.
- `POST /execute/stream` returns Server-Sent Events while the workflow is running.

## Request body

```json
{
  "input": {
    "project_id": 14,
    "task_id": 109
  },
  "secrets": {
    "endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "mcp_summarizer_endpoint": "http://localhost:8000/mcp/summarizer",
    "api_key": "YOUR_API_KEY",
    "models": {
      "flash": "qwen3.6-plus",
      "pro": "qwen3.6-plus",
      "max": "qwen3.6-plus"
    }
  },
  "workflow_source_base64": "..."
}
```

| Field | Type | Description |
| --- | --- | --- |
| `input` | object | Public workflow input. Must match the workflow `input` block. |
| `secrets` | object | Sensitive runtime values. Must match the workflow `secrets` block. |
| `workflow_source_base64` | string | Base64-encoded `.wire` source. |

## `/execute` response

Successful responses return the workflow `output` block as JSON:

```json
{
  "project_id": 14,
  "task_id": 109,
  "summary": "Prepare task dependencies before execution.",
  "next_action": "Fetch the latest task context."
}
```

Errors use a structured JSON body:

```json
{
  "error": {
    "kind": "validation_error",
    "message": "Unknown reference: agent.missing.summary",
    "issues": [
      {
        "path": "agent.writer.instruction",
        "message": "Unknown reference: agent.missing.summary"
      }
    ]
  }
}
```

## `/execute/stream` response

The streaming endpoint uses `text/event-stream`. A typical stream contains lifecycle events, agent events, token or chunk events, and a final completion event.

```text
event: workflow.started
data: {"workflow_id":"..."}

event: workflow.validated
data: {"status":"ok"}

event: agent.started
data: {"agent":"summarize_task"}

event: agent.delta
data: {"agent":"summarize_task","delta":"Prepare"}

event: agent.completed
data: {"agent":"summarize_task","output":{"summary":"...","next_action":"..."}}

event: workflow.completed
data: {"output":{"summary":"...","next_action":"..."}}
```

Error streams terminate with an error event:

```text
event: workflow.error
data: {"kind":"runtime_error","message":"Provider request failed"}
```

## Encoding workflow source

Linux:

```bash
base64 -w0 workflow.wire
```

macOS:

```bash
base64 < workflow.wire | tr -d '\n'
```

## Security notes

- Put credentials in `secrets`, not `input`.
- Avoid logging raw request bodies in production because `secrets` contains provider keys.
- Prefer private networking between the executor and internal MCP servers.
- Keep workflow sources under version control so changes can be reviewed.
