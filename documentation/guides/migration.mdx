---
title: Migration Guide
description: Migrating to the current Superwire DSL from older versions.
---

## `prompt` → `instruction`

The agent property for specifying what the model receives has been renamed.

**Before:**
```wire
agent greeting {
    model: openai("gpt-4.1-mini")
    prompt: "Write a short welcome message."
    output: string
}
```

**After:**
```wire
agent greeting {
    model: openai("gpt-4.1-mini")
    instruction: "Write a short welcome message."
    output: string
}
```

## New `uses:` property

The `tools:` array for inline tool references is still supported, but a new `uses:` property provides better scoping and `max_calls` control.

**Before (inline `tools:`):**
```wire
agent assistant {
    model: openai("gpt-4.1-mini")
    tools: [tool.web_search]
    instruction: "Search and summarize."
    output: string
}
```

**After (with `uses:`):**
```wire
tool web_search from mcp.local.tool.web_search

agent assistant {
    model: openai("gpt-4.1-mini")
    uses: [tool.web_search]
    instruction: "Search and summarize."
    output: string
}
```

## New `dynamic` blocks

Dynamic blocks replace ad-hoc expression embedding for tool calls and MCP operations.

**Before (tool calls in arbitrary expressions):**
```wire
// Not supported or limited
```

**After (dynamic blocks):**
```wire
dynamic {
    data: call tool.fetch_data {
        input { id: input.item_id }
    }
}

agent processor {
    model: openai("gpt-4.1-mini")
    instruction: "Process: {{ dynamic.data }}"
    output: string
}
```

## New MCP server declarations

MCP servers are now declared with `mcp` blocks instead of being embedded in tool references.

```wire
mcp local {
    endpoint: "http://localhost:3000"
    headers: { Authorization: "Bearer token" }
}

tool fetch_user from mcp.local.tool.fetch_user
```

## Batch imports

Multiple tools, resources, or prompts from the same server can be imported in a single `from` block:

```wire
from mcp.local.tool {
    bindings {
        project_id: input.project_id
    }

    tool create_task {
        bindings { task_id: input.task_id }
    }

    tool update_task
}
```

## New reference roots

The grammar now supports additional reference keyword roots:

- `dynamic.*` -- access dynamic block results
- `resource.*` -- reference imported resources
- `prompt.*` -- reference imported prompt templates

Previously, only `agent.*`, `input.*`, `secrets.*`, and `tool.*` were supported.

## `max_calls` for tools

Tool call limits can now be set at the tool declaration level or overridden per-agent:

```wire
tool fetch_data from mcp.local.tool.fetch_data {
    max_calls: 10
}

agent limited_agent {
    uses: [tool.fetch_data { max_calls: 3 }]
    ...
}
```

## Context functions

The `context(...)` and `compact(...)` functions are now fully supported in agent `context:` properties. Use them to control what prior agent output is sent as context to the next agent.

```wire
agent summary {
    model: openai("gpt-4.1-mini")
    context: compact(agent.research_analysis)
    instruction: "Summarize the above."
    output: string
}
```

## Object destructuring in for-loops

Loop patterns now support destructuring:

```wire
// Before: single variable
agent process for item in input.items { ... }

// After: also supports destructuring
agent process for { id, name } in input.items { ... }
```

## Type system changes

### Schema names are now snake_case

Schema names must use `snake_case`:

**Before:**
```wire
schema Participant {
    name: string
}
```

**After:**
```wire
schema participant {
    name: string
}
```

### Nullable values use `maybe`

Nullable values now use `maybe` instead of `| null`:

**Before:**
```wire
schema user {
    name: string
    bio: string | null
}
```

**After:**
```wire
schema user {
    name: string
    bio: maybe string
}
```

### Enums use `enum` keyword

String enums now use the `enum` keyword instead of string literal unions:

**Before:**
```wire
schema release {
    status: "draft" | "ready" | "published"
}
```

**After:**
```wire
schema release {
    status: enum {
        draft
        ready
        published
    }
}
```

### Doc comments for field descriptions

Field descriptions now use doc comments instead of trailing strings:

**Before:**
```wire
schema release {
    title: string "Short human-readable title"
}
```

**After:**
```wire
schema release {
    /// Short human-readable title
    title: string
}
```

### New variant syntax

Variants are now supported for tagged polymorphic objects:

```wire
event: variant type {
    user_created {
        user_id: string
        email: string
    }

    user_deleted {
        user_id: string
        reason: maybe string
    }
}
```

### New match expressions

Match expressions are now supported for variant narrowing:

```wire
user_name: match agent.event_handler.event {
    user_created.user_name
    user_deleted.user_name
}
```

### New null fallback operator

The `??` operator provides fallback values for nullable expressions:

```wire
output {
    name: agent.data.user?.name ?? "Unknown user"
}
```

## Summary of changes

| What changed | Old syntax | New syntax |
| --- | --- | --- |
| Agent instruction | `prompt:` | `instruction:` |
| Tool access | `tools: [tool.xxx]` inline | `uses: [tool.xxx]` with `tool` declarations |
| MCP connection | embedded in tool refs | `mcp` declaration blocks |
| Runtime computation | limited | `dynamic` blocks with `call`, `read`, `render` |
| Reference roots | `agent`, `input`, `secrets`, `tool` | + `dynamic`, `resource`, `prompt` |
| Schema names | `PascalCase` | `snake_case` |
| Nullable values | `Type \| null` | `maybe Type` |
| String enums | `"a" \| "b" \| "c"` | `enum { a, b, c }` |
| Field descriptions | `field: type "desc"` | `/// desc` doc comments |
| Variants | not supported | `variant tag { ... }` |
| Match expressions | not supported | `match value { ... }` |
| Null fallback | not supported | `??` operator |
