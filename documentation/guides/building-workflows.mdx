---
title: Building Workflows
description: A practical workflow-authoring process that starts from outputs and works backward.
---

A good Engine AI workflow usually gets easier to maintain when you design it from the outside in.

## 1. Start with the final output

Decide what the caller should receive.

```txt
output {
    title: agent.release_summary.title
    summary: agent.release_summary.summary
    risks: agent.release_review.risks
}
```

## 2. Define reusable schemas early

When multiple agents or outputs share a structure, give it a name.

```txt
schema ReleaseSummary {
    title: string
    summary: string
    key_points: [string; 3]
}
```

## 3. Keep providers explicit

Declare model backends up front and list allowed models so validation can catch mistakes.

```txt
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}
```

## 4. Keep prompts focused

Prefer small, typed stages over one huge prompt.

```txt
agent summarize_notes {
    model: openai("gpt-4.1-mini")
    prompt: "Summarize these notes into three findings: {{ input.notes }}"
    output: {
        findings: [string; 3]
    }
}
```

## 5. Wire dependencies by reference

Downstream stages should read from upstream stages through `agent.*` references.

```txt
agent create_brief {
    model: openai("gpt-4.1-mini")
    prompt: "Turn these findings into a brief: {{ agent.summarize_notes.findings }}"
    output: schema.ReleaseSummary
}
```

## 6. Keep workflow output stable

The top-level `output` block is the contract you expose to callers. Resist the urge to mirror every internal field directly.

## Checklist

- providers are named clearly
- secrets never appear in prompts or output
- agent outputs have explicit types
- shared shapes use named schemas
- public output is smaller than internal agent output
- model names are listed in each provider for validation
