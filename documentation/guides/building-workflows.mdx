---
title: Building Workflows
description: A practical process for designing maintainable workflows.
---

A good workflow is easiest to maintain when you design the output first and work backward.

## 1. Decide the API response

```wire
output {
    task_id: input.task_id
    summary: agent.summarize.summary
    next_action: agent.summarize.next_action
}
```

## 2. Define input and secrets

```wire
input {
    project_id: number
    task_id: number
}

secrets {
    endpoint: string
    api_key: string
    models: {
        flash: string
        pro: string
        max: string
    }
}
```

## 3. Add provider aliases

```wire
provider ai {
    driver: "openai"
    endpoint: secrets.endpoint
    api_key: secrets.api_key
    models: {
        flash: secrets.models.flash
        pro: secrets.models.pro
        max: secrets.models.max
    }
}
```

## 4. Use schemas for reusable shapes

```wire
schema task_summary {
    summary: string
    next_action: string
    priority: enum { low, medium, high }
}
```

## 5. Add small agents

```wire
agent summarize {
    model: ai("flash")
    instruction: "Summarize task {{ input.task_id }} in project {{ input.project_id }}."
    output: schema.task_summary
}
```

## 6. Add tools only when needed

```wire
tool fetch_task from mcp.tasks.tool.fetch_task {
    bindings {
        project_id: input.project_id
    }
    output {
        title: string
        description: string
    }
}

dynamic {
    task: call tool.fetch_task {
        input {
            task_id: input.task_id
        }
    }
}
```

## Checklist

- The final `output` block is stable and small.
- Credentials are declared in `secrets`.
- Agents return object-shaped outputs.
- Downstream agents reference structured fields, not whole paragraphs where avoidable.
- Tools have schemas, bindings, and `max_calls` when appropriate.
- Independent work is split into separate agents for parallel execution.
