---
title: Best Practices
description: Patterns and conventions for writing maintainable Superwire workflows.
---

## Design from the output backward

Start by defining the `output` block, then work backward to determine which agents and data sources you need.

```wire
// 1. What do I need?
output {
    report: agent.report_renderer
    metadata: agent.metadata_collector
}

// 2. What agents produce those fields?
agent report_renderer { ... }
agent metadata_collector { ... }

// 3. What inputs do they need?
input { ... }
```

## Keep agents small and focused

Each agent should do one thing well. Avoid monolithic prompts.

```wire
// Bad: one agent doing everything
agent everything {
    instruction: "Read the data, analyze it, format a report, and write a summary email."
    output: { ... }
}

// Good: small, composable agents
agent data_reader {
    instruction: "Read and summarize the key data points."
    output: { points: [string] }
}

agent analyzer {
    instruction: "Analyze these data points: {{ agent.data_reader }}"
    output: { insights: [string] }
}
```

## Use schemas for shared types

If multiple agents or the output block reference the same structure, define it once.

```wire
schema Summary {
    title: string
    body: string
    word_count: number
}

agent intro_writer {
    output: schema.Summary
}

agent conclusion_writer {
    output: schema.Summary
}
```

## Protect secrets

- Always use `secrets` for API keys, passwords, and tokens.
- Never reference `secrets.*` in `instruction` or `output` -- the validator will catch it.
- Use secret references in provider configuration:

```wire
secrets {
    openai_key: string
}

provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: secrets.openai_key
    models: ["gpt-4.1-mini"]
}
```

## Use `uses:` for tool access

Prefer the `uses:` property for agent tool access. It makes dependencies explicit and enables per-agent `max_calls` limits.

```wire
tool search from mcp.local.tool.search

agent researcher {
    model: openai("gpt-4.1-mini")
    uses: [tool.search { max_calls: 5 }]
    instruction: "Research: {{ input.topic }}"
    output: string
}
```

## Use `dynamic` for complex runtime computation

When you need tool calls or MCP operations that don't fit in `uses:`, use `dynamic` blocks:

```wire
dynamic {
    data: call tool.fetch_data
}

agent processor {
    instruction: "Process: {{ dynamic.data }}"
    output: string
}
```

## Leverage parallel execution

Structure workflows so independent agents run in parallel. Avoid unnecessary sequential chains.

```wire
// These two run concurrently:
agent sentiment {
    instruction: "Analyze sentiment of {{ input.text }}"
    output: string
}

agent topics {
    instruction: "Extract topics from {{ input.text }}"
    output: [string]
}

// This waits for both:
agent combine {
    instruction: "Combine results: sentiment={{ agent.sentiment }}, topics={{ agent.topics }}"
    output: string
}
```

## Add field descriptions

Descriptions help tooling and collaborators understand your schema:

```wire
schema ReleaseNote {
    title: string "One-line summary of the change"
    impact: "low" | "medium" | "high" "How impactful is this change?"
}
```

## Use optional chaining for nullable fields

Prevent runtime errors with `?.` on nullable paths:

```wire
output {
    score: agent.data.details?.score
}
```

## Validate early, validate often

Always call `validate_workflow` in your CI pipeline and tests. Parse errors and validation issues surface before any execution happens.
