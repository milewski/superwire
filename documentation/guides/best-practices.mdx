---
title: Best Practices
description: Author workflows that validate cleanly, stay readable, and remain easy to evolve.
---

## Prefer named schemas over repeated inline objects

Inline objects are great for tiny cases, but named schemas make large workflows easier to read and reuse.

## Always declare `models` in providers

The provider `models` list enables validation to catch typos before runtime.

## Give every externally useful agent an `output` type

Typed outputs turn ambiguous model responses into explicit contracts.

## Keep secrets in `secrets`, never in `input`

Validation protects `secrets.*` from leaking into prompts and output. That protection only works if sensitive values are modeled as secrets.

## Keep prompts data-rich and instruction-light

Prefer:

- explicit fields from upstream agents
- small, typed intermediate stages
- stable public `output` contracts

Over:

- giant prompts with multiple jobs
- whole-object references when only one field is needed
- exposing raw internal agent output directly to callers

## Use optional chaining only where the type really is nullable

`?.` is most readable when it reflects an actual `| null` branch in your type definitions.
