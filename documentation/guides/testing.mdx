For application-level tests, call the Docker executor with a known workflow and deterministic test secrets.

## HTTP smoke test

```bash
WORKFLOW_SOURCE_BASE64=$(base64 -w0 hello.wire)

curl -s http://localhost:8080/execute \
  -H 'Content-Type: application/json' \
  -d @payload.json
```

A useful `payload.json` fixture contains:

```json
{
  "input": {
    "name": "Test User"
  },
  "secrets": {
    "endpoint": "http://localhost:9000/v1",
    "api_key": "test-key",
    "models": {
      "flash": "test-fast",
      "pro": "test-pro",
      "max": "test-max"
    }
  },
  "workflow_source_base64": "..."
}
```

## What to test

- missing required `input` fields
- missing required `secrets` fields
- unknown model aliases
- invalid agent references
- invalid tool references
- successful `/execute` output shape
- `/execute/stream` lifecycle and final completion event

## Rust-level tests

Use the Rust runtime when you are contributing to Superwire internals or embedding it directly. See [Rust API](/api-reference/rust-api) for parse, validate, and runner-level interfaces.
