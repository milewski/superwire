---
title: OpenAI
description: Configure Superwire to use the OpenAI API as a model provider.
---

## Provider declaration

```wire
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini", "gpt-4.1"]
}
```

## Required settings

| Setting | Description |
| --- | --- |
| `driver` | Must be `"openai"` |
| `endpoint` | API endpoint URL |
| `api_key` | OpenAI API key (use `secrets` in production) |

## Optional settings

| Setting | Description |
| --- | --- |
| `models` | List of allowed model names for validation |

## Agent binding

```wire
agent summarizer {
    model: openai("gpt-4.1-mini")
    instruction: "Summarize the following: {{ input.text }}"
    output: string
}
```

## Using secrets for the API key

In production, store your key in `secrets`:

```wire
secrets {
    openai_api_key: string
}

provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: secrets.openai_api_key
    models: ["gpt-4.1-mini"]
}
```

## Named model arguments

The `model` call supports named arguments:

```wire
model: openai(model: "gpt-4.1-mini")
```

This is equivalent to the positional form `openai("gpt-4.1-mini")`.
