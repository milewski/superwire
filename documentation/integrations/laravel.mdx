---
title: Laravel
description: Call the Superwire executor from a Laravel application.
---

Laravel applications normally call the executor over HTTP. Store provider credentials in Laravel config or environment variables, then pass them as `secrets` in the request body.

## Example request

```php
use Illuminate\Support\Facades\Http;

$workflowSourceBase64 = base64_encode(file_get_contents(resource_path('workflows/task_summary.wire')));

$response = Http::post('http://superwire-executor:8080/execute', [
    'input' => [
        'project_id' => 14,
        'task_id' => 109,
    ],
    'secrets' => [
        'endpoint' => config('services.ai.endpoint'),
        'api_key' => config('services.ai.api_key'),
        'mcp_summarizer_endpoint' => config('services.mcp.summarizer_endpoint'),
        'models' => [
            'flash' => config('services.ai.models.flash'),
            'pro' => config('services.ai.models.pro'),
            'max' => config('services.ai.models.max'),
        ],
    ],
    'workflow_source_base64' => $workflowSourceBase64,
]);

$result = $response->throw()->json();
```

## Streaming

Use `/execute/stream` when the frontend should receive workflow progress or token chunks. In Laravel, proxy the SSE stream rather than buffering the entire response.

## Operational guidance

- Keep workflow files in `resources/workflows` or another reviewed path.
- Keep secrets in `.env` or your secret manager.
- Do not log raw executor payloads because they contain API keys.
- Validate that the returned JSON shape matches the controller response contract.
