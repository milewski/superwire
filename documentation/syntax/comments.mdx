---
title: Comments
description: Use `//` and `///` comments to annotate workflows and document schema fields.
---

Superwire supports two types of comments.

## Single-line comments

Use `//` for general workflow comments:

```wire
// Provider defines where the model comes from.
provider ollama {
    driver: "ollama"
    endpoint: "http://localhost:11434"
    models: ["qwen3.5:8b"]
}
```

### Rules

- comments start with `//`
- comments run to the end of the line
- comments can appear on their own line or after a value

```wire
input {
    topic: string // Topic supplied by the caller
}
```

## Doc comments

Use `///` for field documentation. Doc comments are preserved into generated JSON Schema descriptions.

```wire
schema user {
    /// Stable user identifier
    id: string

    /// Display name shown to other users
    name: string

    /// Optional biography. The field exists, but may be null.
    bio: maybe string
}
```

### Rules

- doc comments start with `///`
- doc comments run to the end of the line
- doc comments are placed before the field they document
- doc comments are preserved in the AST for tooling

### Usage

Doc comments work on:

- schema fields
- inline object fields
- variant case fields

```wire
schema release_note {
    /// Short human-readable title
    title: string

    /// Severity bucket
    impact: enum {
        low
        medium
        high
    }

    /// Full text of the release note
    body: string
}
```

## Recommendation

- Use `//` for workflow intent and business context
- Use `///` for schema field documentation that should appear in generated JSON Schema
- The best comments explain why a provider, prompt, or output shape exists
