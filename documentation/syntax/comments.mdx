## Single-Line Comments

Use `//` for single-line comments:

```ai
// This is a comment
name <- "Alice"

age <- 30  // Inline comment
```

## Multi-Line Comments

Use `/* */` for multi-line comments:

```ai
/*
This is a multi-line comment
that spans multiple lines
*/

provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}
```

## Documenting Workflows

Add comments to explain workflow logic:

```ai
// Configuration
provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

// User input
user_query <- "What is AI?"

// Step 1: Analyze the query
<- agent analyzer {
    model <- "ollama/qwen3:8b"
    prompt <- "Analyze this query: {{ user_query }}"
}

// Step 2: Generate response based on analysis
<- agent responder {
    model <- "ollama/qwen3:8b"
    prompt <- "Answer based on analysis: {{ analyzer.text }}"
}
```

## Commenting Agents

Document agent purpose and behavior:

```ai
// Primary content generator
// Uses GPT-4 for high-quality output
<- agent generator {
    model <- "openai/gpt-4"
    prompt <- "Generate content"
}

// Quality checker
// Validates the generated content meets requirements
<- agent validator {
    model <- "ollama/qwen3:8b"
    prompt <- "Validate: {{ generator.text }}"
}
```

## Inline Documentation

Add context to complex expressions:

```ai
price <- 100
tax_rate <- 0.08  // 8% sales tax
shipping <- 15    // Flat rate shipping

// Calculate total with tax and shipping
total <- (price * (1 + tax_rate)) + shipping
```

## Section Headers

Organize workflows with comment headers:

```ai
// ============================================
// CONFIGURATION
// ============================================

provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

// ============================================
// DATA PROCESSING
// ============================================

<- agent processor {
    model <- "ollama/qwen3:8b"
    prompt <- "Process data"
}

// ============================================
// OUTPUT GENERATION
// ============================================

<- agent formatter {
    model <- "ollama/qwen3:8b"
    prompt <- "Format output: {{ processor.text }}"
}
```

## TODO Comments

Mark areas for future work:

```ai
// TODO: Add error handling
// TODO: Implement retry logic
// FIXME: This prompt needs improvement

agent task {
    model <- "ollama/qwen3:8b"
    prompt <- "Perform task"
}
```

## Best Practices

<Tip>
  Write comments that explain WHY, not WHAT. The code shows what it does; comments should explain the reasoning.
</Tip>

```ai
// Good: Explains reasoning
// Use GPT-4 for complex analysis because local models struggle with nuance
agent analyzer {
    model <- "openai/gpt-4"
    prompt <- "Analyze sentiment"
}

// Avoid: States the obvious
// This agent analyzes sentiment
agent analyzer {
    model <- "openai/gpt-4"
    prompt <- "Analyze sentiment"
}
```

<Warning>
  Keep comments up to date. Outdated comments are worse than no comments.
</Warning>

## Examples

### Documented Workflow

```ai
/*
Multi-Agent Content Pipeline
1. Generate initial draft
2. Review and improve
3. Format for publication
*/

provider ollama {
    driver <- "ollama"
    config <- { endpoint <- "http://localhost:11434" }
    models <- ["qwen3:8b"]
}

// Input topic
topic <- "Artificial Intelligence"

// Stage 1: Draft generation
<- agent drafter {
    model <- "ollama/qwen3:8b"
    prompt <- "Write a draft about: {{ topic }}"
}

// Stage 2: Content review
// Checks for accuracy and clarity
<- agent reviewer {
    model <- "ollama/qwen3:8b"
    prompt <- "Review and improve: {{ drafter.text }}"
}

// Stage 3: Final formatting
// Prepares content for publication
<- agent formatter {
    model <- "ollama/qwen3:8b"
    prompt <- "Format for publication: {{ reviewer.text }}"
}
```
