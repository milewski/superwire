---
title: Control Flow
description: The current grammar-level control flow feature is the agent `for` loop.
---

The current DSL has one explicit control-flow construct: looping an agent over a collection.

## Syntax

```txt
agent <name> for <item_name> in <expression> {
    ...
}
```

## Example

```txt
input {
    numbers: [number]
}

agent input_number_note for n in input.numbers {
    model: openai("gpt-4.1-mini")
    prompt: "Write a short note for input number {{ n }}"
    output: {
        number: number
        note: string
    }
}
```

## Common iterable sources

- input arrays: `input.items`
- agent-produced arrays: `agent.findings.items`
- inline literals: `[1, 2, 3, 4]`

## Expected result shape

Referencing a looped agent returns an array of outputs:

```txt
output {
    notes: agent.input_number_note
}
```

## Current runtime status

<Warning>
  The parser and validator support loop syntax, but the current default runtime
  does not execute looped agents yet and returns `UnsupportedForLoop`.
</Warning>

Use this syntax when documenting or validating the language, but do not rely on it in the default runtime until execution support lands.
