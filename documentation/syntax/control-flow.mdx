---
title: Control Flow
description: The current grammar-level control flow feature is the agent `for` loop.
---

The current DSL has one explicit control-flow construct: looping an agent over a collection.

## Syntax

```ai
agent <name> for <item_name> in <expression> {
    ...
}
```

## Example

```ai
input {
    numbers: [number]
}

agent input_number_note for n in input.numbers {
    model: openai("gpt-4.1-mini")
    prompt: "Write a short note for input number {{ n }}"
    output: {
        number: number
        note: string
    }
}
```

## Common iterable sources

- input arrays: `input.items`
- agent-produced arrays: `agent.findings.items`
- inline literals: `[1, 2, 3, 4]`

## Expected result shape

Referencing a looped agent returns an array of outputs:

```ai
output {
    notes: agent.input_number_note
}
```

## Current runtime behavior

Looped agents execute in the default runtime.

Each loop iteration produces one output item, and referencing the looped agent returns the full output array.

## Parallel iteration

The runtime executes loop iterations in parallel when possible:

```ai
agent persona_campaign for persona in input.personas {
    model: openai("gpt-4.1-mini")
    prompt: "Create a campaign for persona: {{ persona }}"
    output: {
        persona: string
        tagline: string
    }
}
```

## Nested loop references

You can chain looped agents:

```ai
agent persona_campaign for persona in input.personas {
    model: openai("gpt-4.1-mini")
    prompt: "Create a campaign for {{ persona }}"
    output: {
        persona: string
        tagline: string
    }
}

agent persona_score for campaign in agent.persona_campaign {
    model: openai("gpt-4.1-mini")
    prompt: "Score this campaign: {{ campaign }}"
    output: {
        persona: string
        score: number
    }
}
```
