---
title: References and Identifiers
description: Understand names, keyword roots, dot access, and optional chaining.
---

References are how one part of a workflow reads values from another part.

## Identifier rules

Identifiers:

- start with a letter or underscore
- continue with letters, digits, or underscores

Examples:

- `openai`
- `release_summary`
- `_internal`

## Keyword roots

The language reserves these reference roots:

- `agent` -- access agent outputs
- `input` -- access input fields
- `secrets` -- access secret values
- `dynamic` -- access dynamic block results
- `tool` -- reference imported tools
- `resource` -- reference imported resources
- `prompt` -- reference imported prompts

Examples:

```wire
input.topic
secrets.openai_api_key
agent.summary
agent.summary.title
dynamic.config.threshold
tool.fetch_user
resource.user_list
prompt.system_instructions
```

## Dot access

Use `.` to access a nested field.

```wire
agent.summary.title
input.customer.profile.name
dynamic.result.values
```

## Optional chaining

Use `?.` when a nullable object may be `null`.

```wire
agent.typed_example.nullable_object?.string_value
```

Validation allows optional chaining when the path can be followed through the declared type. At runtime, `?.` returns `null` instead of failing when the current value is `null` or the field is absent.

## Bare identifiers

The grammar allows a plain identifier as a reference root. This is mainly useful for loop variables and function-call syntax.

```wire
agent remediation_plan for finding in agent.findings.items {
    instruction: "Create a remediation plan for {{ finding }}."
    output: string
}
```

<Warning>
  The current default runtime only resolves keyword-root references such as
  `agent.*`, `input.*`, `secrets.*`, `dynamic.*`, `tool.*`, `resource.*`, and
  `prompt.*`. Plain identifier references are not resolved during runtime
  execution today.
</Warning>
