---
title: Quickstart (Rust)
description: Build and run a small Superwire workflow using Rust code.
---

This quickstart shows how to parse, validate, and execute Superwire workflows from Rust. It uses Ollama as the model provider because it is the lowest-friction way to run a real workflow locally.

## 1. Start a model provider

Install and start Ollama, then pull a model:

```bash
ollama pull qwen3.5:8b
```

## 2. Create a workflow

Save this as `hello.wire`:

```wire
provider ollama from ollama {
endpoint: "http://localhost:11434"
}

model ollama_model from ollama {
    id: "qwen3.5:8b"
}

agent greeting {
    model: model.ollama_model
    instruction: "Write a one-sentence welcome message for a new user."
    output: string
}

output {
    greeting: agent.greeting
}
```

Note the **`instruction:`** property -- not `prompt:`. This is the agent property that holds the text sent to the model.

## 3. Execute it from Rust

The `try_workflow!` macro simplifies workflow execution by combining parsing and running:

```rust
use superwire_core::runtime::try_workflow;
use schemars::JsonSchema;
use serde::Deserialize;

#[derive(Debug, Deserialize, JsonSchema)]
struct Output {
    greeting: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let workflow_output: Output = try_workflow!("hello.wire").await?;

    println!("{}", workflow_output.greeting);

    Ok(())
}
```

## 4. Add input values

Typed input makes workflows reusable:

```wire
provider ollama from ollama {
endpoint: "http://localhost:11434"
}

model ollama_model from ollama {
    id: "qwen3.5:8b"
}

input {
    topic: string
    audience: string
}

agent summary {
    model: model.ollama_model
    instruction: "Explain {{ input.topic }} for {{ input.audience }}."
    output: {
        title: string
        summary: string
    }
}

output {
    title: agent.summary.title
    summary: agent.summary.summary
}
```

The `try_workflow!` macro also works with inputs:

```rust
use superwire_core::runtime::try_workflow;
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, JsonSchema)]
struct Input {
    topic: String,
    audience: String,
}

#[derive(Debug, Deserialize, JsonSchema)]
struct Output {
    title: String,
    summary: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let input = Input {
        topic: "agent workflows".to_string(),
        audience: "Rust developers".to_string(),
    };

    let workflow_output: Output = try_workflow!("summary.wire", input).await?;

    println!("{:?}", workflow_output);

    Ok(())
}
```

<Tip>
  If you want deterministic tests without a live model, use
  `WorkflowRuntime::run_with_runner(...)` with a custom `AgentRunner`. The testing guide
  shows the full pattern.
</Tip>

## 5. Know the current runtime boundary

The default runtime executes `model`, `instruction`, `output`, `context`, `inference`, `tools`, `uses`, `for` loop agents, `context(...)`, `compact(...)`, and `template(...)`.

Dynamic blocks, MCP server integrations (`mcp` declarations, tool calls via `call`, resource reads via `read`, prompt renders via `render`), and batch imports are also supported.

<Info>
  `tool.*` references are resolved through the MCP tool system and are only available
  within agent <code>uses:</code> arrays or <code>dynamic</code> blocks. The
  <code>call tool.xxx</code> expression form is used in dynamic blocks.
</Info>
