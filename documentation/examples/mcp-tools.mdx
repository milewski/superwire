## Full workflow

```wire
provider openai {
    driver: "openai"
    endpoint: "https://api.openai.com/v1"
    api_key: "test-api-key"
    models: ["gpt-4.1-mini"]
}

secrets {
    mcp_endpoint: string
}

mcp local {
    endpoint: secrets.mcp_endpoint
}

input {
    project_id: number
    task_id: number
}

tool fetch_task_data from mcp.local.tool.fetch_task_data {
    bindings {
        project_id: input.project_id
        task_id: input.task_id
    }
}

dynamic {
    data: call tool.fetch_task_data
}

agent summarizer {
    model: openai("gpt-4.1-mini")
    instruction: "Summarize: {{ dynamic.data }}"
    uses: [tool.fetch_task_data]
    output: {
        summary: string
    }
}

output {
    data: dynamic.data
    summary: agent.summarizer.summary
}
```

## What it demonstrates

- MCP server declaration with secrets for credentials
- Tool import with `bindings` that reference input fields
- `call tool.xxx` expression in a `dynamic` block to invoke the tool at runtime
- Agent `uses:` to declare tool dependencies
- Combining `dynamic` block results with agent output

## Alternative: batch tool import

Multiple tools from the same server can be imported together:

```wire
from mcp.local.tool {
    bindings {
        project_id: input.project_id
    }

    tool create_sorting_task {
        bindings { task_id: input.task_id }
    }

    tool update_task_status {
        bindings { task_id: input.task_id }
    }

    tool assign_task {
        bindings { task_id: input.task_id }
    }
}

agent task_manager {
    model: openai("gpt-4.1-mini")
    uses: [tool.create_sorting_task, tool.update_task_status, tool.assign_task]
    instruction: "Manage project tasks"
    output: string
}
```

## Limiting tool calls

Use `max_calls` to restrict how many times a tool can be invoked:

```wire
tool fetch_shared from mcp.local.tool.fetch_task_data {
    max_calls: 2
    bindings {
        project_id: 1
        task_id: 2
    }
}

agent first_agent {
    model: openai("gpt-4.1-mini")
    uses: [tool.fetch_shared { max_calls: 1 }]
    instruction: "First"
    output: string
}
```

Per-agent `max_calls` overrides the tool-level default.

## Tool output schema override

You can override the expected output type of a tool:

```wire
tool fetch_numbers from mcp.local.tool.fetch_numbers {
    output {
        values: [number]
    }
}

dynamic {
    result: call tool.fetch_numbers
}

agent number_note for number in dynamic.result.values {
    model: openai("gpt-4.1-mini")
    instruction: "Write a note for {{ number }}."
    output: string
}
```

This lets you define the shape the tool returns, enabling downstream type checking and loop iteration.
